Security and trust

Neuron can open, change and run files in your projects. This page explains when it asks first, what it sends where, and what Zero-X keeps.

Trusting a folder

The first time you start Neuron in a folder, it asks whether you trust it. A project can ship its own Neuron settings (.neuron.json or .neuron/settings.json), and those settings can:

  • run hooks: commands that run before or after Neuron uses a tool;
  • start MCP servers: programs that give Neuron extra tools;
  • add permission rules that let Neuron do more without asking;
  • choose which model provider your requests go to.

A repository you cloned from someone else could use these to run code on your computer. Until you trust the folder, Neuron ignores all four. Trust a folder only if you created the project or trust where it came from.

  • Trust is saved for the folder's git root, in trusted_dirs.txt in your Neuron home folder (~/.neuron by default). Remove a line there to stop trusting that folder.
  • You can trust every project under a folder you own with trustedRoots in your user settings (~/.neuron/settings.json). Project settings cannot do this.
  • For scripts and CI, NEURON_TRUST_WORKSPACE=1 trusts the current folder for that run only.

Permissions while it works

Trusting a folder does not let Neuron do anything it likes. The permission mode decides what it may do on its own:

ModeWhat Neuron may do without asking
read-onlyRead and search files, and run read-only commands such as git status. It cannot edit files or run other commands.
workspace-writeAlso edit files in the project. Any other command asks for your approval first.
danger-full-accessEdit files and run any command without asking. Use it only in a disposable environment.
  • Whatever the model reads is sent to the model provider. Neuron therefore always asks before it reads .env files and settings or credential files, in every mode, and directory searches skip them.
  • When Neuron asks, the prompt shows the command it wants to run or the file it wants to change.
  • Switch modes with /permissions or start with neuron --permission-mode <mode>.

What leaves your computer

  • Your requests. Each turn sends your message, the conversation so far and whatever files or command output Neuron included, to the model provider you chose. When you sign in with Zero-X, that goes through the Zero-X gateway to the provider that serves the model. With your own provider key, it goes straight to that provider and never passes through Zero-X.
  • Sign-in. neuron auth login opens Zero-X in your browser and stores a session token on your computer.
  • No analytics. Neuron does not send usage analytics or crash reports to Zero-X. Sessions and history stay on your computer.
  • Free model tiers. Some providers' free tiers may use prompts to improve their models and may let people review them. The privacy policy lists every provider. Do not send secrets or code you may not share on the Free plan.

What Zero-X stores

The gateway stores usage metadata only: time, model, provider, status, token counts, cost, latency and a request ID. It does not store the text of your prompts, files or the model's responses; request content is held in memory only while it is forwarded. Retention periods are in the privacy policy.

Provider API keys stay on the gateway and are never sent to Neuron or the website. CLI sessions and API keys are stored only as SHA-256 hashes.

Your account and devices

  • When Neuron asks to sign in, the browser page shows the device name, its IP address and location, and warns you if the request comes from another country. Approve only a request you started.
  • Signed-in CLI sessions last 30 days. Sign out of every CLI session from the dashboard if a computer is lost or a token may have leaked.
  • API keys are shown once. Revoke one from the dashboard and it stops working at once.

Report a security problem

Email support@zero-x.live with "Security" in the subject. Describe what you found, how to reproduce it and what it affects. Please do not test against other people's accounts or data, and give us a reasonable time to fix the problem before you publish it. We reply within 2 business days.

For anything else, see help and support.
