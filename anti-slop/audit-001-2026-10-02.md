## How the repository works

- Main marketing pages are standalone HTML with inline CSS and JavaScript. Tailwind is generated in visitors' browsers through a CDN script; fonts and Supabase SDK also come from third parties.
- `zerox-auth.js` is shared by homepage, product page, and dashboard. It fetches `/auth/config` and initializes Supabase only when configured.
- The Hono Worker in `neuroncli/auth-server/src/index.js` serves host-specific pages, authentication configuration, and online AI APIs. Wrangler bundles the repository root as static assets. A push to main deploys through `.github/workflows/deploy.yml`; GitHub Pages is also enabled.
- The homepage interactive search is a JavaScript mock dataset. It does not invoke the desktop application's retrieval engine or access visitors' files.
- The six platform download links target release `v1.0.0-build-202610010440` in the separate `deepseekfs` repository. All six assets exist in the release API response.

## Numbered findings

### 1. HIGH: sign-in is unconfigured (R-26, R-27)

Reason: the visible Sign In action currently ends in an authentication configuration error instead of opening a working flow.

Evidence: clicked Sign In on `www.zero-x.live/neuron.html`; received "Supabase authentication is not configured for this environment." Live `/auth/config` returned `configured: false`, with URL and publishable-key presence both false. `zerox-auth.js:283` initializes conditionally; `zerox-auth.js:338` rejects an unconfigured client. The Worker reads `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` or `SUPABASE_ANON_KEY` at `neuroncli/auth-server/src/index.js:139`.

Proposed fix: configure the existing Supabase project in the Cloudflare environment and verify authorized providers and callback URLs. Never substitute a service-role key. This requires the existing project's correct settings; none were invented or printed during verification. Until available, show a truthful unavailable state. Downloads remain available independently.

### 2. HIGH: visitor figures include simulated data (R-17, R-36)

Reason: random active users and estimated growth are presented as measured traffic.

Evidence: `index.html:818` creates random active users, `index.html:829` extrapolates baseline counts, and failure handlers at `index.html:862` and `index.html:896` increment synthetic totals. CounterAPI successes do not validate those fallback numbers; session counting also does not establish unique people.

Proposed fix: remove simulated counts and display only sourced analytics, with accurate metric names. Do not use these figures to report campaign reach or real users.

### 3. HIGH: faint text fails contrast (R-25)

Reason: small text in the shared faint color is difficult to read.

Evidence: `zx-faint` is `#4E4E5A` against background `#0A0A0C` in `index.html:55` and `neuron.html:52`. The installed `antislop-human/contrast-check.py` measured **2.41:1**, below both normal and large-text thresholds. Examples include product footer text and download notes. This measured pair is a confirmed failure; gradient and transparent-surface combinations need their own checks during a fix.

Proposed fix: brighten the faint text token and check its actual rendered surfaces while preserving the restored layout.

### 4. HIGH: mobile menu lacks accessible behavior (R-32, R-03)

Reason: the product menu cannot close with Escape and its opener is too small and unnamed.

Evidence: at a 390 x 844 viewport, product `#mobBtn` measured **24 x 31 px** with no `aria-label`, below the skill's 44 px target. Opened the menu, pressed Escape, and confirmed it remained visible; the close button worked. `neuron.html:194` defines the opener and `neuron.html:759` implements click-only menu behavior. No focus management or expanded-state update exists. Homepage uses the same click-only pattern at `index.html:753`.

Proposed fix: label and enlarge controls, add Escape handling, focus management, and expanded state to both menus.

### 5. HIGH: mock search looks like real product evidence (R-38, R-17)

Reason: fixed scores, document counts, and latency values are displayed without identifying the search as a simulation.

Evidence: homepage "Interactive NeuCockpit" switches to hardcoded `mockDataset` at `index.html:1103`; it advertises 30,000+ files and fixed vault counts at `index.html:350` and `index.html:377`. It returns all mock results when nothing matches at `index.html:1151`. Product page also contains realistic fabricated category results at `neuron.html:344`. This is not measured desktop retrieval performance.

Proposed fix: explicitly label sample data and simulation, remove unmeasured counts and latency, and use a genuine app recording for proof if approved.

### 6. HIGH: demo controls promise unavailable actions (R-26, R-32)

Reason: vault buttons and copy-path affordances have no action.

Evidence: the four vault buttons at `index.html:375` through `index.html:386` have no handler; rendered result cards use `cursor-pointer` and a "Copy local path" span at `index.html:1154` through `index.html:1173` without copying or opening anything. Their labels imply interaction.

Proposed fix: present them as static sample labels, or implement only clearly useful demo actions with keyboard support. No new backend is needed.

### 7. HIGH: product facts need reconciliation (R-36, R-38)

Reason: restored copy conflicts with current implementation and release metadata.

Evidence: `neuron.html:432` and `neuron.html:668` say Qwen Coder 3B, but current `deepseekfs/services/model_manager.py:26` specifies `Qwen/Qwen2.5-Coder-1.5B-Instruct-GGUF`. JSON-LD at `neuron.html:78` says 2.4 GB; the six installer assets currently range from 1,231,711,160 to 1,364,963,153 bytes. "No cloud, no data ever leaves" at `neuron.html:456` is unqualified despite the online mode described at `neuron.html:655` and the website's authentication/online AI services. The 15-day trial copy and "Zero subscriptions" on `index.html:542` also need a confirmed product policy rather than assumptions.

Proposed fix: update the model and size facts from release evidence, qualify offline claims by mode, and use the owner's confirmed trial/pricing terms consistently in visible copy and structured data.

### 8. HIGH: subdomain route behavior is inconsistent (R-24, R-26)

Reason: the product subdomain's root and explicit index path serve different pages.

Evidence: live `https://neuron.zero-x.live/` serves the NeuCockpit product page, while `https://neuron.zero-x.live/index.html` returns the Zero-X homepage title. In `neuroncli/auth-server/src/index.js:19`, the generic dotted-path asset branch precedes the explicit subdomain `/index.html` rewrite at line 39. Some product footer company links intentionally use relative `index.html`; they must be audited when normalizing routing. The main homepage NeuCockpit link successfully reaches the product root. This inconsistency is confirmed, but it has not been established as the cause of the user's original symptom.

Proposed fix: define one host/path contract, make company links explicit, and resolve host HTML routes before generic assets. Verify home, product, dashboard, and their explicit HTML paths together.

### 9. MEDIUM: motion and decoration lack recorded purpose (R-01, R-19)

Reason: orbs, floating elements, gradient glows, and scroll reveals are stacked without a documented hierarchy or usability goal.

Evidence: animation definitions in `index.html:100` and `neuron.html:91`, plus `.reveal` opacity rules at `index.html:113` and `neuron.html:100`. Neither page contains a reduced-motion override. Content remains hidden if the reveal script cannot run. The campaign has a working pause button, which should be retained.

Proposed fix: keep decoration that supports the approved brand direction, document its purpose, honor reduced motion, and make content visible by default. Retain the old composition unless explicitly approved otherwise.

### 10. LOW: generic CTA labels obscure the next action (R-15)

Reason: "Learn more" and "Explore NeuCockpit" are less specific than the destination they open.

Evidence: `index.html:263` and `index.html:544` show generic labels linking to the product page.

Proposed fix: use labels such as "See NeuCockpit and downloads" without changing layout.
